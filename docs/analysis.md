# Olist 电商履约体验诊断与复购基线分析

个人学习项目｜SQL 数据分析与产品需求探索

整理日期：2026-11-20

## 项目摘要

基于 Olist 公开电商数据，使用 MySQL、Python/Pandas 和 Jupyter 完成数据入库、订单级建模、质量检查、履约与评分分层分析、完整观察期复购统计及评论试标。结果提示，配送延迟与低评分存在关联，但准时订单也出现质量、缺件和售后问题。基于这些线索提出订单状态查询与收货异常反馈候选方案，并规划验证指标。项目未实施线上功能或实验，未检验延迟与后续复购的直接关系。

## 数据与分析方法

- 导入8张核心表，覆盖99,441笔原始订单；地理定位表未纳入本轮核心分析。
- 商品、支付明细分别按订单预聚合，再关联；使用 ROW_NUMBER 按订单保留最新评价参与分析，原始评价记录仍保留。
- 核对入库行数、订单唯一性、商品/运费/支付金额及缺失。订单视图仍为99,441行，三项金额差额均为0。
- 主履约分析窗口为2017年1月至2018年8月。延迟按实际签收日晚于预计送达日计算；缺失或无效日期不进入延迟率分母。低分定义为1～2分，以有效最新评分订单为分母。
- 品类分析中，单一品类订单归入对应品类，多品类和品类信息不全订单单列；展示结果仅保留至少100笔符合条件订单的品类组。
- 使用 CTE、多表关联、条件聚合、窗口函数和日期计算开展分层及复购分析；使用 Pandas 关联人工标签与样本元数据，并拆分多标签汇总。

## 主要结果

### 履约与评分

主窗口内，日期有效的已送达订单96,203笔，延迟6,531笔，延迟率6.79%，平均配送时长12.54天。延迟组低评分率62.42%，准时组9.25%，相差53.17个百分点。

RJ地区延迟率12.14%，涉及1,495笔延迟订单。RJ内部，延迟组与准时组低评分率分别为73.08%和10.89%，相差62.19个百分点；按购买月份分组后，20个月的差异方向均一致，但11个月的延迟组评价不足30条。上述结果描述关联，未充分控制品类、卖家等差异。

RJ地区 bed_bath_table 品类有1,329笔符合条件的订单，其中201笔延迟，延迟率15.12%。结合受影响订单数量与发生比例，将其作为优先调查对象之一；不认定它是全部业务的最优先问题。

### 复购基线

以 customer_unique_id 识别买家，合并同日购买，以数据中首次符合成交条件的购买作为首购。统一68,617名买家，首购发生于2017年1月至2018年4月，使用2018年8月1日之前的购买记录，留足90天观察窗口。

| 累计观察窗口 | 买家数 | 跨日复购买家数 | 累计跨日复购率 |
|---|---:|---:|---:|
| 30天 | 68,617 | 450 | 0.66% |
| 60天 | 68,617 | 708 | 1.03% |
| 90天 | 68,617 | 888 | 1.29% |

三个窗口为累计关系，复购买家数不能相加。随观察窗口延长，累计复购率上升属于观察期变化，不代表运营提升。公开样本中的首购不一定是真实首购，未观察到复购也不等于流失。

### 评论核验

目标品类1,329笔订单中，674笔有评论正文，正文覆盖率50.71%。按延迟与评分交叉为四组，各固定抽取10条，共40条。先用前10条确定规则，剩余30条由AI辅助标注，最终逐条人工核对与修订，保留葡语原文依据。

| 评论主题 | 延迟且低分 | 延迟且非低分 | 准时且低分 | 准时且非低分 |
|---|---:|---:|---:|---:|
| 未收货（是否超期不明） | 4 | 2 | 2 | 0 |
| 配送时效 | 2 | 1 | 0 | 0 |
| 物流信息 | 1 | 1 | 0 | 0 |
| 商品质量/描述 | 1 | 0 | 3 | 2 |
| 错发/缺件 | 0 | 0 | 3 | 0 |
| 售后 | 0 | 0 | 1 | 0 |
| 其他明确问题 | 0 | 1 | 1 | 0 |
| 无明确问题 | 1 | 4 | 0 | 8 |
| 不确定 | 2 | 3 | 0 | 0 |

每组分母仅为10条，允许多标签，各标签不能相加作为独立评论数。“无明确问题”不等于满意。样本用于发现问题线索和完善规则，不能推算全部订单投诉率。最终已送达订单中出现未收货表述，需要核对评论和签收时点后解释，不能直接认定数据错误。

## 产品假设及验证计划

候选方向为订单状态查询与收货异常反馈：在订单详情集中展示预计送达日期、最近物流更新时间及对应反馈入口，覆盖未收到、部分收到和物流信息疑问等场景，并明确处理状态及下一步操作。

本次评论仅支持继续调查收货异常体验，尚不能证明查询或反馈入口是问题根源。先通过访谈和原型任务测试，观察状态理解准确率、正确找到处理入口及反馈任务完成率，关注重复/无效反馈和人工处理负担。若验证支持该方向，再规划小范围随机对照试验，并新增页面行为、物流与客服处理数据。

这是待验证产品方案。当前未完成该方案的用户访谈、原型验证、线上实验或业务效果评估，不声称降低物流延迟、提升评分或复购。评论AI辅助仅是分析过程，未开发或上线自动分类功能。

## 已完成与保留问题

已完成本轮数据准备、基础指标、地区/月度/品类诊断、统一观察期复购基线、40条评论试标与人工核对，以及候选方案和验证计划。本项目可作为SQL与产品分析学习案例收尾。
