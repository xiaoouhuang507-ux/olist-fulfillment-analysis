# 评论试标口径

在里约热内卢州的床品、餐桌及卫浴用品类订单中，1,329 笔符合履约分析条件，其中 674 笔有评论正文。将有有效评分和正文的订单按延迟与评分交叉分为四组，每组固定抽取 10 条。抽样 SQL 用稳定的订单哈希排序，可复现各组样本条数。

先用 10 条确定规则，再对其余 30 条进行 AI 辅助试标，最终逐条人工核对。标注依据是葡语原文，译文用于辅助理解。一条评论可有多个问题标签。

| 判断 | 采用的标签 |
| --- | --- |
| 用户明确说还没收到，但无法确认是否已超过承诺日期 | 未收货（是否超期不明） |
| 评论明确描述超过预计日期或到货过慢 | 配送时效 |
| 评论提及物流追踪、状态或更新方面的问题 | 物流信息 |
| 商品质量或实物与描述有出入 | 商品质量/描述 |
| 收到错误商品或订单缺少组件 | 错发/缺件 |
| 涉及退换货、联系商家或售后处理 | 售后 |
| 文本未描述具体问题，或证据难以判断 | 无明确问题 / 不确定 |

[报告中的分组汇总](analysis.md#评论核验)展示了问题线索。比如延迟且低分组 10 条样本里有 4 条提到未收货，准时且低分组有 3 条提到质量或描述问题、3 条提到错发或缺件。样本经分层等量抽取，且不同组的正文覆盖率不同，不能把上述数量换算为整体投诉率。

仓库的[评论查询](../sql/07_review_coverage.sql)只输出聚合计数。人工试标的原评论、逐条标签和订单识别列保留在本地。
